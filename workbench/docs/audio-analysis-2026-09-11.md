# 分析与原音：2026-09-11 实现说明

> 历史记录：研究模式、真人标注、JSON 导出及重说 Judge 已于 2026-09-16 前移除。本文保留当时的探索与实现背景，不代表当前功能；产品方向以 [最新 PRD](../../prd.md) 为准，当前实现见 [练习应用](../README.md)。

产品决策：分析的定位、证据与解释优先；普通重说由用户回听判断。自动 Judge 仅保留在研究工具。最多 8 项候选是上限，不是数量目标，Top-1 默认展开，其余按时间选择。

## 官方 API 核验

- [Gemini 音频理解](https://ai.google.dev/gemini-api/docs/generate-content/audio)：可联合分析音频和文本、引用时间片段。当前继续使用 generateContent 和结构化 JSON，没有迁移接口或更换模型。模型生成的时间不作为最终播放边界。
- [Scribe API](https://elevenlabs.io/docs/api-reference/speech-to-text/convert)：词级时间、logprob、speaker_id；启用 diarize，取消英语强制提示，保留自动语言结果。说话人分离和语言概率是辅助信号，不是独立事实。
- [Forced Alignment](https://elevenlabs.io/docs/api-reference/forced-alignment/create)：给定音频和文本对齐，返回词/字符时间和 alignment loss。当前不新增这次调用；错误转写的强制对齐不能解决内容真实性，loss 也不是发音分数。
- TTS 继续使用现有 with-timestamps 参考声音；参考声音不能证明原录音发音错误。

## 实现

1. 每个转写词有 word_index。Coach 返回 inclusive start/end word index；服务器检查边界、时序，从 Scribe 重建 excerpt 和时间。未知或重叠时间不伪造精度；不可靠候选定位会导致分析校验失败。
2. 播放片段使用浏览器解码后裁切 PCM WAV，不再依赖 timeupdate 事件及时停止。解码按 Blob 弱引用缓存。原始录音、候选和重说仍在当前会话内存；结束释放引用。超出实际音频的范围明确报错。
3. 词间间隔从相邻 ASR 词边界计算，0.3 秒以上展示，排除重叠、无效时间和明确的说话人切换。不是 VAD 静音测量。提示要求结合原音判断停顿是否打断句法或意群，时长不能单独决定错误。
4. 回听导航按标点、0.6 秒间隔或最多 16 词粗分，不宣称为模型确认的意群；点击词语可选择包含它的分段，支持正常/慢速、循环、同步词高亮。
5. 用词候选说明当前词义、搭配或指代造成的具体影响，保留数字、否定与请求强度；不从一次样本推断长期习惯。
6. 发音候选必须有 audio 证据，提示要求具体可听辨差异与可能混淆，禁止从拼写猜音素、编造舌位或给发音分数。输出字段的校验只能验证声明，不能验证模型真的听对。

## 验证与限制

- 已覆盖词索引越界、模型猜测时间被替换、原句重建、无效时间线、发音缺少声音证据、超过 3 项候选、间隔/说话人切换、分段、PCM 裁切及越界拒绝。
- 类型检查、Lint、生产构建和本地测试通过。沙箱下 tsx CLI 的 IPC 管道不可用，使用 `node --import tsx --test tests/*.test.ts` 运行相同测试。
- 浏览器检查了示例结果的转写导航、无原音禁用状态和普通重说无自动判分状态。未用真人录音跑付费 API；尚未完成设备回放听测、真实模型契约稳定性和精准度验证。
- 下一轮评估应覆盖：清楚但有口音、错误转写、自然停顿、动宾之间异常停顿、数字/否定、搭配误用和含混辅音；由目标听者核对定位、误报和解释。新提示不等于经过验证的精准诊断。
